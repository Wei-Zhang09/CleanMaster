### UNINST-2 的取舍（为什么没用 MangoDisk 的 explorer 令牌方案）

MangoDisk 用 `CreateProcessWithTokenW` 把卸载器放到 explorer 令牌下跑。本机评估后放弃：
① 该 API 需要 `SeImpersonatePrivilege`，非提权场景直接失败，而失败模式（卸载器起不来）比问题本身更糟；
② 真正会出错的是「用**另一个**管理员账户提权」，那种情况下我们连枚举到的都是管理员的 HKCU，
   换个令牌启动也救不回来，只能拒绝并引导用户换身份运行；
③ 同账户提权时 HKCU 本就正确，换令牌只是多绕一圈。
结论：校验 + 拒绝 + 说明，比"想办法让它跑起来"更诚实也更安全。

明确不抄：把服务当启动项一键禁用、计划任务全量暴露、注册表整键事务删除、批量卸载、静默卸载默认开启。

## 明确不做

- 不做 Rust / Tauri 重写（成本 3–6 月，收益是常数因子与体积，不解决兼容性）。
- 不恢复 CleanMaster-Win10 分支。
- 不为了「对齐 MangoDisk」而引入 WebView2 依赖。
